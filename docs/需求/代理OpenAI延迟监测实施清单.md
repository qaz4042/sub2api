# 代理 OpenAI 延迟监测实施清单

状态：待实施。本文仅规划，不代表已开发、测试或部署；实际完成并验证后再打钩，不授权部署、发布或推送。

## 一、范围与统一口径

为选定代理开启后台监测，支持每 10／30／60 秒采样，记录成功与失败；代理页查看最近状态和历史趋势，关闭页面后继续采样。默认全部关闭，开启时默认间隔 30 秒，首版仅按代理配置。

首版不含批量配置、多代理对比、告警、自动切换、账号恢复、模型推理测速、自定义目标或通用任务平台。结果不参与现有代理健康判定、账号统计、用量或计费；手动测速保持原有行为，不计入定时样本。

| 项目 | 统一约定 |
| --- | --- |
| 探测目标 | 复用 `https://api.openai.com/v1/models`，不发送账号密钥、不调用生成接口 |
| 成败 | HTTP 200／401 为连通成功；403、429、5xx、连接失败、超时分别记录并计为失败 |
| 延迟 | 复用现有 prober，计时从发起请求到响应头返回，不含随后读取响应体的耗时；客户端复用连接，仅新连接包含建连、TLS 等耗时，不代表 TTFT 或模型速度 |
| 汇总 | 成功率 = 成功数 / 已完成样本数；平均延迟、P95 仅用成功样本，失败不填 0ms；无样本或全失败时延迟为空 |
| 缺测 | 未采样、暂停、调度跳过、服务停机不计成败；展示样本数、最近采样时间和过期状态，趋势缺失桶留空 |
| 时间 | UTC 存储、用户时区展示，查询区间左闭右开 |
| 配置隔离 | 协议、地址、端口、凭证的连接指纹与监测调度版本分开；连接变化后当前状态不沿用旧结果，单纯调整采样间隔不切断同一连接的历史，历史不保存连接密码 |
| 保留期 | 原始样本保留 7 天，定时分批清理；先按原始样本查询聚合 |

## 二、架构与开工边界

沿用仓库分层，以独立文件组织 `proxy_openai_monitor`，公共代码仅留下表接入点；前端放在 `features/proxy-openai-monitor/`，目录以开工时主干为准，不为整齐搬迁核心代码。

| 独立实现 | 必要公共接入 |
| --- | --- |
| 探测适配 | 现有目标 prober、结果类型及最小 contract，复用网络请求逻辑 |
| Runner、租约与并发控制 | 生命周期、依赖装配 |
| 配置、样本、统计与清理 repository | 追加 migration、现有数据库客户端 |
| 管理 handler、DTO | 管理员路由注册 |
| 配置／统计弹窗、API client | 代理页入口、必要语言包键 |

- [ ] 核对当前分支及上游最新版本的等价能力，记录基线 commit，只补缺失部分；本任务不顺带升级整个主干。
- [ ] 记录并隔离未提交改动，不覆盖或夹带模型改动、临时浏览器产物；功能文件不含真实域名、Token、代理密码或服务器配置。
- [ ] 列出实际公共接入点，每种边界只留必要接入；不扩大账号定时测试、用量或网关核心接口，不复制核心、不搭通用插件框架，仅为实际复用增加小接口。
- [ ] migration 使用实施时下一个唯一编号，不修改历史；通用修复与本 feature 独立提交，优先回馈上游。

以上遵循《主干能力迁移代办》的能力隔离、追加 migration、最小接入与单一意图原则；旧分支、提交、编号和验收记录仅作背景。其引用的《开源更新与能力扩展手册》当前路径不存在，如需引用先核对位置。

## 三、闭环 A：配置后持续采样

### 配置与存储

- [ ] 独立配置表：代理 ID、开关、间隔、配置版本、下次执行时间、租约及更新时间；每代理最多一份，现有代理不自动开启。
- [ ] 样本表：代理 ID、连接指纹、调度版本、计划执行标识、开始／结束时间、成功标记、可空延迟、HTTP 状态、脱敏错误分类；增加代理与时间查询索引、执行标识唯一约束。
- [ ] 代理采用软删除，领取与查询均排除已删除代理，不依赖外键级联；由 feature 清理任务分批清理其配置与历史，在删除提示说明。其余样本按 7 天保留期分批清理，不引入永久分钟汇总表。

### 执行与恢复

- [ ] 复用现有 prober，保持约 10 秒超时及手动测速语义；探测失败与保存失败分别记录，数据库错误不计为线路失败。
- [ ] 独立 Runner 按秒扫描到期配置，不依赖分钟级账号 cron；采用有限 worker、有限待处理量并错开初始执行时间，校验代理可监测及并发额度，跳过时记录运行状态。
- [ ] 数据库原子领取并设置有期限的租约，覆盖探测与保存上限；正常情况下同一代理仅一个任务，允许极端卡顿、租约到期时出现重复探测，以拒绝失效 worker 落库保证结果一致性，不增加复杂分布式锁。
- [ ] 领取时捕获连接指纹；保存结果及推进调度时，原子校验租约有效期、所有者、执行标识、调度版本及当前代理连接指纹和可监测状态。读取当前状态也须匹配连接指纹，暂停或配置变化后旧任务不得更新当前结果或调度。
- [ ] 按计划时刻推进，积压或执行超周期时跳过过期轮次，不补跑、不无限排队、不主动重叠探测或自动重试；间隔为目标周期，10 秒档遇到接近超时的请求可能跳轮，属于缺测。允许调度偏差，不以“执行完成再等一个周期”充当固定周期采样。
- [ ] 暂停、停用、过期、删除后停止新任务；未启用时不产生探测流量，运行异常仅影响监测，不阻断业务请求。
- [ ] 退出时停止领取，取消或有界等待运行任务；崩溃后租约到期可恢复，不补跑停机数据。

### 管理入口与验收

- [ ] 独立管理员配置读取／更新 API，沿用认证与权限保护；服务端校验代理存在、状态及间隔枚举。
- [ ] 代理页增加“监测”入口，配置弹窗仅含开关和间隔，保存后显示明确状态。
- [ ] 验收：开启单个代理后关闭页面仍持续采样；暂停后停止新任务，其他代理不受影响。

## 四、闭环 B：历史可查、统计可解释

- [ ] 独立统计 API 返回配置、当前状态、汇总、趋势、分页最近记录，以及实际覆盖区间、样本数、截断信息。
- [ ] 提供近 1 小时／24 小时／7 天，服务端限制最长区间、桶数、分页大小并设置查询超时，校验 SQL 索引计划。
- [ ] 整体 P95 按查询区间成功原始样本计算；桶内指标独立计算，不平均桶级 P95 或百分比充当整体统计。
- [ ] 近 1 小时按分钟、较长区间按小时聚合，图表标明粒度；最近记录提供 10 秒级明细。
- [ ] 展示成功率、成功平均延迟、P95、失败次数、最近采样时间；趋势显示成功延迟与失败次数，区分失败和缺测，过期阈值采用明确的周期倍数，并覆盖探测超时、保存上限及调度余量；UI 说明延迟口径及跳轮行为。
- [ ] 复用现有弹窗、图表、筛选样式，不复制账号统计大组件或调用其用量／计费 API；仅打开弹窗时刷新，关闭、切换代理或区间时取消旧请求并防止过时响应覆盖，刷新不修改采样调度。
- [ ] 补齐加载、空数据、全失败、接口失败及窄屏状态。
- [ ] 验收：同一区间汇总与样本一致，失败不折算为 0ms；配置隔离、时区展示、快速切换正确。

## 五、按风险做最小充分验证

| 验证层 | 必须覆盖的风险 |
| --- | --- |
| Go 单元测试 | 间隔校验、到期推进、超时跳轮、并发上限、停用／配置变化、保存失败、退出取消 |
| PostgreSQL 集成测试 | 多 worker／实例领取竞争、租约恢复、旧 worker 写入、连接变化后旧结果拒写、幂等保存、软删除竞争及清理；空库及已有代理数据的 migration 升级 |
| 查询集成测试 | 成败混合、全失败、无数据、区间边界、P95、版本隔离、保留期清理 |
| 权限与脱敏 | 未登录／非管理员不可读写配置及历史，错误不含代理凭证 |
| 前端定向测试 | 配置保存、空／失败状态、切换取消、过时响应；类型检查及涉及文件的 lint |
| 本地浏览器 | 配置到统计闭环；默认关闭时手动测速、代理健康、自动切换、账号定时测试不变 |
| 容量与查询 | 用本地可控探测桩验证目标规模：每代理每天 8,640 条，10 个代理 7 天约 60 万条 |

- [ ] 完成对应验证并记录结果；不使用文档中的线上 Token，不以线上持续探测替代本地验证。
- [ ] 执行 `git diff --check`，检查依赖、migration、公共文件差异；只在发现相关风险时扩大测试范围。

## 六、提交与交付

- [ ] 按闭环 A、B 拆分可运行、可验证的提交，各含对应测试与说明；首次交付同时具备持续采样与基本历史查看。通用 prober 修复单独提交并标记可回馈上游部分，不为拆分重写历史。
- [ ] 记录公共接入文件与符号、API 契约、migration 编号、测试命令、保留策略及关闭方式；汇总实际验收结果后打钩。
- [ ] 验证关闭监测停止任务，已有数据继续按 7 天策略清理；版本回退前核对数据库兼容性，不自动删表或回滚历史 migration。
- [ ] 合并上游优先保留核心与安全修复，再适配接入点；出现等价能力时评估替换，避免长期维护重复实现。

后续按需另立闭环，不阻塞首版：

- 长期趋势或实测查询压力：增加分钟汇总与 90 天保留，保存计数、延迟总和等可合并数据；P95 使用原始数据或明确的可合并分布方案。
- 多代理管理成本上升：增加批量开启／暂停、多代理对比。
- 明确业务需求：增加告警或自动切换，单独定义误判、恢复阈值及权限。
