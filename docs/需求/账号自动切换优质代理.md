# 账号自动切换优质代理

状态：已完成本地实现与定向验证；默认关闭，未部署。原有监测和账号统计文档仅作为背景，本设计不改变其采集口径。

## 最小闭环

账号管理 → 独立 OpenAI 账号操作菜单 →「自动切换优质代理」。打开开关并保存，新配置默认使用“全部符合条件的代理”；也可选择“指定代理”，手选 2–10 条候选线路（包含当前代理）。已有配置保持指定池，不自动扩大。候选需启用、未过期、已开启 OpenAI 监测且未配置固定主备。主动优化等待足够监测样本，不强制轮换 IP。

| 项目 | 规则 |
| --- | --- |
| 评估 | 目标每 30 秒一次；主动优化使用最近 5 分钟监测，故障处理使用当前近 5 分钟及候选近 1 小时的真实请求 |
| 请求成功率 | 只计算已识别的成功请求和上游传输失败；鉴权、限额、HTTP 状态失败及无法归因的失败不计入分母 |
| 业务候选样本 | 业务故障对比使用同账号、同模型、同入口类型（HTTP 或 WebSocket）的至少 5 个已识别请求，成功率 ≥80%；主动优化不要求业务候选历史 |
| 辅助连通 | 候选代理监测开启、新鲜、覆盖充分，近 5 分钟成功率 ≥80% 且最近 3 次成功；用于避免选到明显不可达的线路 |
| 故障／降级 | 当前代理最近一次为持久传输错误、近 5 分钟连续 3 次传输失败，或至少 5 个已识别请求中成功率 <80%；传输故障可使用监测合格但无账号历史的冷启动候选，HTTP 5xx 仍须有符合条件的真实请求候选 |
| HTTP 5xx | 同模型、同入口连续 3 次 5xx，且候选近 5 分钟至少 2 次成功、最近一次成功晚于该组首个连续 5xx，才可切换；缺少证据时暂停监测延迟择优并清空其确认进度，实际请求恢复后重新确认。明确传输故障仍可走故障切换 |
| 主动优化 | 当前与候选均满足监测资格；候选近 5 分钟监测 P95 同时改善 ≥30% 且 ≥200ms，选择 P95 最低候选；同一候选连续 3 次评估达标且每次两侧均有新探测才切换 |
| 防抖 | 正常切换后冷却 5 分钟；确认故障可在 1 分钟后再次切换 |
| 无解 | 监测不足、采集有缺口或没有合格候选时保持绑定 |
| 停用 | 关闭开关后保留当前绑定，不自动还原旧线路，不回落直连 |

“一个代理可能只稳定两小时”以滑动窗口应对，不使用两小时轮换定时器。正常择优使用监测延迟，不使用不同业务请求的首字耗时。确认传输故障时，可使用新鲜、覆盖充分、近 5 分钟成功率 ≥80% 且最近 3 次成功的监测候选冷启动；切换后的真实请求继续采集，用于后续故障判断。鉴权、限额和无法归因的失败不触发该冷启动。账号手工改绑会暂停托管，重新启用后才继续采集。此版本采用固定策略，暂不提供大量可调阈值。

## 账号与并发边界

- 仅接管显式开启的独立 OpenAI 账号；不接管影子账号、直连账号或已处于固定主备回退状态的账号。账号不活跃时暂缓评估。
- 全部模式每轮动态解析符合条件的代理，新代理自动参与，不受页面 500 条展示限制；可能改变出口地区，管理员须确认这些代理均适合账号。也可指定候选池；当前没有地区、供应商和容量自动约束。
- 页面展示已保存范围中监测合格的备选数量（不含当前代理）；实际切换仍受延迟差距、连续确认及冷却限制。为零时提示检查监测，不主动试用。
- 固定主备模式与本功能互斥；指定池中任一代理改成主备模式后暂停切换并显示冲突；全部模式自动排除非当前的主备代理，当前绑定出现主备冲突仍暂停。过期／停用的候选自动失去资格，其他健康候选仍可参与。
- 保存配置记录当前绑定为预期值。下一轮发现手工改绑、直连或外部回退时，自动关闭托管并显示原因。外部改绑发生在自动事务提交之后时，以外部写入为准，随后评估关闭托管。
- 每账号配置行使用 `FOR UPDATE SKIP LOCKED`；锁顺序为配置、账号、按 ID 排序的代理、监测配置。连续确认状态与账号切换同事务保存，配置修改、连接指纹变化、候选变更或监测不合格时重置；多实例不重复执行同一轮。
- 账号改绑、路由相关 API-key 探测快照失效、scheduler outbox 通知与切换审计同事务提交。母账号切换时，其已有影子账号按宿主规则同步代理并逐个通知快照更新；影子不独立配置策略。创建影子时事务内锁定母账号并读取最新绑定，避免与改绑并发产生旧代理。调度快照按宿主既有 outbox 消费机制更新，已开始的请求与长连接不会强制断开。
- 因实际传输故障切换时，仅清除带宿主 `upstream transport error (proxy/network):` 前缀的临时不可调度状态，其他限额或临时状态保留。旧代理的迟到传输错误设置临时状态时按当次代理 ID 校验，防止覆盖新线路状态。
- 配置保存使用版本校验，冲突返回 409；关闭不要求候选仍有效，也不依赖历史样本查询成功。
- 单次评估上限三秒；失败回滚，单独标记稍后重试，避免一个账号阻塞其他账号。后台每五秒最多处理 32 个账号，超量或慢查询时评估可能延后。

## 监测口径与观察

复用 `proxyopen.ReadQuality` 校验候选连通性，仅统计当前连接指纹的近五分钟已完成探测；200/401 仍只表示连通，不代表授权请求或模型调用成功。真实请求观察与探测分开存储，仅采集已开启功能的账号：记录成功、确认传输失败和已识别的上游 HTTP 5xx，以及账号、当次代理连接指纹、模型、入口类型和可选首字耗时。无请求体、密钥或错误内容。

成功用量日志有 `first_token_ms`，但无当时代理 ID；失败日志可能有代理 ID，但受监控开关、错误类型和关联能力限制，不能与成功用量直接计算准确成功率。故不按当前绑定回填历史；采集从启用之后开始，不发起额外测试请求。实际请求数据是已识别的上游尝试，不是全部用户请求的成功率；5xx 单独计数，不计入传输成功率分母。5xx 采集限于已接入入口类型报告的 Responses、Messages、Chat Completions 及对应 WebSocket 的 failover 路径，不涵盖所有 API 或已提交的流错误。鉴权、限额、客户端取消及无法归因的失败不作为代理故障。首字耗时仅供观察，不用于主动择优。配置页按候选展示近一小时最多 5 组模型和入口的实际样本，旧历史的未知入口不能用于故障比较。

采集使用有界异步队列，不阻塞请求；启用、进程启动、队列溢出或写入失败按账号标记采集缺口，暂缓该账号切换。数据库大范围不可用时，各实例会标记此前启用的账号。切换事务提交前复核数据库缺口版本和本实例的本地版本；其他实例尚未将缺口异步写入数据库时仍有短暂传播窗口。原始观察保留 1 天，决策仅使用近 1 小时；切换日志只保存账号／代理 ID、原因和时间，页面显示最近 20 条。后台有界分批清理过期观察和超过 30 天的日志，存在积压时加快继续清理。

## 独立实现与迁移

| 层 | 实现／最小 contract |
| --- | --- |
| feature | `backend/internal/features/proxyquality/`：开关、候选池、策略、事务、worker、管理员 API |
| 监测输入 | `backend/internal/features/proxyopen/quality.go`：`ReadQuality(ctx, tx, ids, now)`，只读、无凭证输出 |
| 宿主写适配 | feature 内 `bindings.go`：唯一账号更新与 outbox 适配位置；迁移时优先适配上游已有写入接口 |
| 请求观察接入 | `service/openai_account_observer.go`：可选观察接口；既有调度结果和传输失败各一处通知，HTTP／WS 入口提供请求类型，不改计费 |
| 通用并发修复 | `repository/account_shadow_proxy_create.go`：创建时锁母账号并读取绑定；`account_transport_cooldown.go`：旧代理的迟到故障不封禁新线路 |
| 装配 | `handler/admin/proxy_openai_monitor.go`：`ProxyMonitorRuntime` 组合两个独立 worker，复用已鉴权代理路由组和停机入口 |
| 数据 | 新增 `250_account_proxy_quality.sql`、`251_account_proxy_quality_observations.sql`、`252_account_proxy_quality_safety.sql`、`253_account_proxy_quality_scope.sql`、`254_account_proxy_quality_monitor_confirmation.sql`，不修改历史 migration 或 Ent 生成模型 |
| 前端 | `frontend/src/features/account-proxy-quality/`：入口按钮、独立弹窗、API、请求状态与中英文文案 |
| 前端接入 | `AccountActionMenu.vue` 转发事件；`AccountsView.vue` 挂载弹窗 |

管理员 API：`GET/PUT /api/v1/admin/proxies/account-auto-switch/:account_id`。写入字段为 `enabled`、`all_eligible`、`proxy_ids`、`version`；缺省 `all_eligible=false` 兼容旧客户端，新账号读取默认 true。全部模式的 `proxy_ids` 仅保留指定池草稿；关闭时也可保存候选池草稿。读取额外返回达标备选数量 `candidate_count`、当前绑定、最近决策、评估时间、切换时间、可选代理和最近日志。最多列出 500 个有效候选，需要更多时再扩展搜索接口。沿用宿主管理员鉴权；受限管理密钥未登记此操作权限，按既有白名单默认拒绝。

迁移到新 `main`：先确认 OpenAI 监测输入能力，再迁移独立 feature 和只读 contract，将新 migration 以目标分支的下一序号追加并重生成 Wire。核对调度结果、传输失败、HTTP 5xx 和 HTTP／WS 入口观察点是否仍然存在，以及账号写入、影子继承、路由快照失效和 outbox 语义。影子创建并发修复独立迁移，优先回馈上游。关闭所有开关即可停用；移除装配前先关闭开关，保留当前账号绑定及审计表即可。

## 本地验证

监测延迟择优变更：隔离 PostgreSQL 下 `proxyquality` 与 `proxyopen` 的 race 测试通过，覆盖新探测确认、阈值、候选或连接变化、配置重置、故障优先、事务与审计；前端 feature 测试、类型检查和定向 ESLint 通过。未部署。

本次范围简化验证：隔离 PostgreSQL 下 `go test -race ./internal/features/proxyquality` 通过，覆盖动态新增、停用／主备排除、旧客户端指定池兼容与关闭保留绑定；前端 feature 10 项测试、类型检查及定向 ESLint 通过。本次未新增浏览器视觉验证，未部署。

- 策略测试：同模型、同入口比较，样本不足、采集缺口、故障降级和冷却边界。
- 隔离 PostgreSQL + race：默认关闭、配置版本、候选校验、旧指纹隔离、主备冲突、手工改绑、并发只切一次、审计与 outbox 原子回滚、失败账号不阻塞后续、路由相关探测失效、影子创建与改绑并发、管理员路由边界。
- 前端：开关与候选池校验、不可选候选的关闭路径、切换历史、旧响应取消、保存冲突／状态未确认、账号菜单回归，类型及 ESLint 检查。
- 浏览器：本地弹窗 fixture + 模拟 API，桌面与窄屏检查；未以真实账号验证模型业务请求，未部署。

复现后端：设置 `PROXY_QUALITY_TEST_DSN` 指向可创建临时 schema 的隔离 PostgreSQL，执行 `go test -race ./internal/features/proxyquality`。原监测回归另设 `PROXY_MONITOR_TEST_DSN` 后执行 `go test -race ./internal/features/proxyopen`。
